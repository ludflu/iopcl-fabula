# Parallel child generation preserves search semantics

When one refinement produces several children (mostly from `establishers` in open-condition and open-motivation planning, and from `discoverFrames` in `afterEstablish`), building each child runs `finalize`, threat updates and sometimes frame discovery. Those builds are independent. We parallelize them with `parMap` when the candidate list is at least four items and the RTS offers more than one capability (`+RTS -N`). List order is unchanged, so node numbering, tie-breaking and flaw choice stay the same as sequential code. We do not parallelize picking which flaw to refine, ranking flaws by child-count estimate, or expanding multiple frontier nodes. Parallelism is off when `IPCL_PARALLEL_MIN` is set to a large value (tests) or the RTS is single-threaded.
