# Search strategies share one event stream, and only a complete search says Exhausted

Best-first, beam search and Monte Carlo tree search all produce the same `[SearchEvent]` stream: one `Visited` per `expand` call, plus `FoundSolution`. So node limits, time-outs, tracing, `--count` and the distinct-Story filter in `IPOCL.solve` work for every strategy without knowing which one is running. An incomplete strategy that stops on its own (an empty beam layer) ends its stream with `GaveUp`, which `solve` reports as `LimitHit`. A stream that simply ends means the whole space was searched, which `solve` reports as `Exhausted` when no Story was found. We chose this because `Exhausted` is a claim that no Story exists, which tests and authors rely on: unmotivated Tower is `Exhausted`. A beam that prunes the only Story must not make that claim. MCTS may still end its stream normally, because when its root is exhausted it really has searched everything.
